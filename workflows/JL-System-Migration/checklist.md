# 遗留系统迁移验证清单 (Migration Checklist)

此清单用于确保 `JL-System-Migration` 工作流的每个阶段都达到“零偏差”的质量标准。

## 阶段 1：领域边界识别 (Scope & Context)
- [ ] **范围明确**: 已明确界定哪些包和类属于本次迁移范围。
- [ ] **依赖清晰**: 所有外部依赖（DB, Redis, RPC）都已识别并列出。
- [ ] **技术债识别**: 关键的技术债（如 SQL 方言、过时 API）已记录在案。
- [ ] **目标确认**: 目标架构（COLA）、JDK 版本、ORM 框架已由用户确认。

## 阶段 2：建立“黄金标准” (The Golden Master)
- [ ] **单元覆盖**: 针对旧系统的核心逻辑，已生成覆盖率 > 80% 的 JUnit 测试。
- [ ] **行为录制**: 已完成关键业务场景的流量/日志录制，并转化为测试用例。
- [ ] **业务契约**: 已生成 Gherkin 或自然语言描述的业务契约（Specification）。
- [ ] **接口契约**: 输入/输出的 JSON Schema 已锁定。

## 阶段 3：数据库迁移 (DB Migration)
- [ ] **Schema 转换**: 旧 DDL 已正确转换为新数据库方言（如 MySQL -> PG）。
- [ ] **类型兼容**: 所有字段类型差异（如 `tinyint` vs `boolean`）已正确映射。
- [ ] **数据校验**: 数据迁移脚本已包含行数校验和关键字段 Sum/Hash 校验。
- [ ] **脚本验证**: 迁移脚本已在测试环境试运行并通过。

## 阶段 4：分层代码重构 (Layered Refactoring)
- [ ] **Infra 层验证**: Repository 实现已通过集成测试，能正确读写新 DB。
- [ ] **Domain 层纯净**: 领域对象不依赖任何框架（Spring/MyBatis）。
- [ ] **业务逻辑迁移**: 所有业务规则已迁移至 Domain/App 层，且无逻辑变更。
- [ ] **TDD 验证**: 每一层代码的实现都已通过“黄金标准”测试集的验证。

## 阶段 5：端到端集成验证 (E2E Verification)
- [ ] **黑盒回归**: 使用“黄金数据集”对新系统进行全量回归，结果完全一致。
- [ ] **配置迁移**: 所有配置项已迁移并适配新环境。
- [ ] **文档完备**: 已生成新系统的运行指南和测试报告。
