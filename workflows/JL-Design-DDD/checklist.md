# DDD 系统设计工作流 - 验证清单

## 产研统一设计阶段验证

### 基本信息完整性
- [ ] 业务背景描述清晰，无歧义
- [ ] 核心诉求使用「动词+对象+目标」格式
- [ ] In-Scope 明确定义本次必须实现的功能
- [ ] Out-of-Scope 明确不做的内容，防止需求蔓延
- [ ] 依赖条件明确业务/技术依赖
- [ ] 利益攸关者分析包含角色、职责、诉求、关注点
- [ ] 数据字典统一所有业务和技术术语

### 业务流程细化
- [ ] 主业务流程按「角色操作→系统响应」步骤拆解
- [ ] 使用 Mermaid 绘制主业务流程图
- [ ] 使用 Mermaid 绘制主业务时序图
- [ ] 分支业务流程包含正常路径和异常处理
- [ ] 分支流程表格包含：分支名称、触发条件、流程描述、涉及角色

### 功能清单
- [ ] 功能点描述包含所有必要字段
- [ ] 每个功能点明确依赖条件（数据库表、第三方接口等）
- [ ] 每个功能点明确对外能力（接口/消息等）
- [ ] 功能点与业务规则正确关联

### 用户故事
- [ ] 用户故事遵循标准格式：[用户类型] 想要 [做什么] 以便 [达到什么目的]
- [ ] 每个用户故事有明确的验收标准
- [ ] 用户故事覆盖所有主要用户场景

### 业务信息汇总
- [ ] 业务规则汇总完整，无遗漏
- [ ] 关键业务信息使用图表描述（如适用）
- [ ] 业务规则与功能点正确关联

### 功能实现分析
- [ ] 系统上下文使用 C4 模型图描述
- [ ] 已实现功能对应到具体代码模块或类
- [ ] 未实现功能明确列出
- [ ] 关键功能实现方案包含技术选型和流程图
- [ ] 数据库设计包含表结构和关系
- [ ] 代码可维护性和扩展性分析完整

---

## 事件风暴阶段验证

### 事件风暴图质量
- [ ] 事件风暴图样式遵守 DDD 与可视化规范
- [ ] 事件风暴图严格对齐业务流程
- [ ] 使用正确的颜色编码：
  - 橙色：领域事件
  - 蓝色：命令
  - 黄色：聚合
  - 粉色：外部系统/用户
  - 紫色：策略/业务规则
- [ ] 图中元素连接关系清晰
- [ ] 时间线从左到右正确排列

### 元素识别完整性
- [ ] 所有领域事件已识别并命名
- [ ] 所有触发命令已识别
- [ ] 所有聚合已初步识别
- [ ] 外部系统/参与者已标识
- [ ] 关键业务规则已标注
- [ ] 潜在热点问题已识别

### 用户交互
- [ ] 与用户进行了充分的对话（至少 5 轮确认）
- [ ] 用户确认事件风暴图的准确性
- [ ] 针对歧义点进行了澄清

## DDD 建模阶段验证

### 业务分析总结
- [ ] 业务场景描述完整
- [ ] 核心流程梳理清晰
- [ ] 关键业务规则列出
- [ ] 问题和热点识别准确

### 领域清单
- [ ] 领域事件清单包含：事件名称、描述、关联逻辑
- [ ] 触发命令清单包含：命令名称、描述、关联逻辑
- [ ] 角色/聚合关联清单完整
- [ ] 业务规则清单包含：适用场景、约束条件、预期结果

### 限界上下文
- [ ] 限界上下文划分合理
- [ ] 每个上下文的核心业务关注点明确
- [ ] 包含的领域元素列举完整
- [ ] 子域类型（核心/通用/支撑）划分正确
- [ ] 划分依据充分说明

### 领域建模
- [ ] 聚合根设计合理，解释选择原因
- [ ] 聚合根属性定义完整
- [ ] 聚合根行为方法定义完整
- [ ] 聚合内实体与值对象设计正确
- [ ] 聚合间关系类型和说明清晰
- [ ] 领域事件与聚合的关联正确
- [ ] 领域事件之间的关系（前驱/后继/并发）正确

### 可视化图表
- [ ] 架构包图呈现 COLA 架构下的包关系
- [ ] 核心领域上下文类图包含聚合根、实体、值对象
- [ ] 关键业务流程的类时序图清晰展示调用关系
- [ ] 跨上下文协作图展示不同限界上下文的协作
- [ ] 关键实体生命周期图展示状态转换
- [ ] 类详细目录结构树状图遵守 COLA 架构规范
